# P1 优先级任务实施计划（并行执行）

## 总体策略

采用**最小化实现 + 快速迭代**的方式，同时进行三个方向的工作，预期 5-7 天完成核心功能。

---

## 第一周：核心功能实施

### 方向 A：轻量级监控系统（Day 1-2）

**目标**：创建实时监控能力，无需额外依赖

**实施步骤**：
1. 创建 `monitoringSystem.ts` - 核心监控服务
   - 内存监控（使用 `process.memoryUsage()`）
   - 成本监控（从 costMonitor 获取）
   - 性能监控（响应时间、错误率）
   - 自动告警机制（5 分钟冷却）

2. 创建 `monitoring.ts` tRPC 路由
   - `getDashboard` - 获取完整仪表板数据
   - `getMemoryMetrics` - 内存指标
   - `getCostMetrics` - 成本指标
   - `getPerformanceMetrics` - 性能指标
   - `triggerMemoryCleanup` - 手动清理（admin only）

3. 创建前端 `MonitoringDashboard.tsx` 组件
   - 内存使用率卡片（实时更新）
   - 成本使用率卡片
   - 性能指标卡片
   - 告警提示区域

4. 集成到仪表板
   - 在 DashboardLayout 添加 Monitoring 菜单项
   - 创建 MonitoringPage 页面

**预期收益**：
- 系统可见性提升 100%
- 问题快速发现能力
- 无额外成本

---

### 方向 B：基础测试体系（Day 1-3）

**目标**：为关键服务建立测试框架

**实施步骤**：
1. 创建测试文件结构
   ```
   server/services/__tests__/
   ├── cacheManager.test.ts
   ├── costMonitor.test.ts
   ├── localLearningEngine.test.ts
   └── monitoringSystem.test.ts
   
   server/routers/__tests__/
   ├── learningLogs.test.ts
   └── monitoring.test.ts
   ```

2. 编写单元测试（使用 vitest）
   - cacheManager：基本操作、过期、清理
   - costMonitor：成本追踪、告警检查
   - localLearningEngine：关键词提取、概念识别
   - monitoringSystem：指标记录、告警触发

3. 编写集成测试
   - learningLogs 路由：获取、搜索、权限
   - monitoring 路由：数据准确性、权限控制

4. 配置 CI/CD
   - 添加 `test` 脚本到 package.json
   - 配置 GitHub Actions（可选）

**预期收益**：
- 代码质量提升
- 快速发现 bug
- 重构信心增加

---

### 方向 C：本地学习优化（Day 2-4）

**目标**：改进本地学习算法质量

**实施步骤**：
1. 改进关键词提取
   - 实现 TextRank 算法（替代简单 TF-IDF）
   - 添加词性标注过滤（保留名词、动词、形容词）
   - 支持中英文混合处理

2. 实现语义相似度分析
   - 使用编辑距离计算词汇相似度
   - 自动合并相似概念（相似度 > 0.8）
   - 构建概念聚类

3. 改进主题识别
   - 使用更好的分词算法
   - 实现简单的主题聚类
   - 提取主题关键词

4. 添加学习质量评分
   - 评估学习深度（基于消息数量和概念数）
   - 评估概念新颖性（新概念数 / 总概念数）
   - 评估学习价值（基于概念重要性）

5. 更新学习日志格式
   - 添加质量评分字段
   - 添加算法版本标记
   - 记录优化后的关键词和概念

**预期收益**：
- 学习效果提升 30-50%
- 概念质量提升
- 无额外成本
